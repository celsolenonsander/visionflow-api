### Contratos implícitos (estrutura de `src/core/shell`)

- **Providers globais**
  - `ThemeProvider`: fornece modo (`light`, `dark`, `system`), cor primária e setters via Context; **não depende de API** (`ThemeProvider.tsx:4-18, 77-111`).
  - Não há `AuthProvider` React: a sessão vem do Zustand persistido em `localStorage` (`useAuthStore.ts:1-25`).
  - `RequireAuth` protege o AppShell verificando apenas a sessão local; não valida sessão via API ao montar (`RequireAuth.tsx:1-14`).
  - A raiz envolve o app em `StrictMode` e `ThemeProvider` (`main.tsx:1-12`); o layout autenticado usa `Outlet` (`App.tsx:12-39`).

- **Formato de erro esperado**
  - Cliente HTTP reconhece envelope com `success`, `data`, `error`; o objeto de erro tipado tem `code?` e `message?` (`apiClient.ts:1-10`).
  - Em resposta HTTP não-OK, procura `message` na raiz ou `error.message`; caso contrário usa mensagem genérica. Para `success: false`, usa `error.message` ou mensagem genérica; `code` não é propagado (`apiClient.ts:46-60, 92-104`).
  - Repositórios/ViewModels convertem erros em strings para telas; não foi encontrado Error Boundary nem provider/toast global nos caminhos analisados.

- **Estados globais**
  - Sessão: estado `user` do Zustand, persistido sob `visionflow:auth` (`useAuthStore.ts:5-25`).
  - Tema: Context, `localStorage` (`visionflow:theme`), classe `dark` no `<html>` e CSS variables (`ThemeProvider.tsx:20-22, 32-44, 77-111`).
  - Loading/error do shell: pertencem ao `useShellViewModel`; não foi encontrado estado global de loading compartilhado entre as features (`useShellViewModel.ts:12-45`).

- **Interceptors/camada HTTP**
  - Não há interceptor separado; `apiRequest` normaliza a barra inicial e concatena o base URL (`apiClient.ts:63-67`).
  - Em body string, adiciona `Content-Type: application/json` se ausente; lê token persistido e adiciona `Authorization: Bearer <token>` se houver e se o header não existir (`apiClient.ts:68-77`).
  - Faz `fetch`, lê texto e tenta parse JSON; remove o envelope retornando `data` quando encontra `success` e `data`; também aceita payload sem envelope (`apiClient.ts:77-104`).
  - Não há refresh de token identificado. A seleção de API é `VITE_USE_API !== 'false'`; em desenvolvimento o base URL é relativo; fora de desenvolvimento usa `VITE_API_BASE_URL` ou `http://localhost:8080` (`apiClient.ts:12-21`).
